Do código à demonstração: uma sequência verificável, sem instalar bibliotecas e sem alterar os arquivos de entrada.

Maurício Taguchi · 3 de novembro de 2026

Comece por aquiPrepararExecutarInterpretarPreservar arquivosTreinar a explicaçãoLimites

1. Obtenha o exemplo completo

Use Python 3.11 ou superior. Para obter todos os arquivos com Git, execute os comandos abaixo em uma pasta de trabalho. Eles criam uma nova pasta portfolio; não os execute por cima de uma cópia com alterações locais.

git clone https://github.com/MauricioTaguchi/portfolio.git
cd portfolio

Sem Git, use Code → Download ZIP no repositório, extraia o arquivo e abra um terminal na pasta extraída. O exemplo usa somente a biblioteca padrão do Python; não precisa de Node.js, Docker ou chave de API.

2. Rode testes e demonstrações

No Windows:

py -B public/blog/exemplos/run_examples.py

No macOS ou Linux:

python3 -B public/blog/exemplos/run_examples.py

O executor roda as duas suítes, demonstra a restauração de revisões, verifica os códigos de saída das amostras e compara os arquivos de entrada antes e depois. Por padrão, o relatório é criado em uma pasta temporária e removido ao terminar.

3. Confira o resultado, não só a mensagem

O resumo final deve ter estes valores:

{
  "status": "passed",
  "valid_fixture_exit": 0,
  "invalid_fixture_exit": 1,
  "invalid_records": 6,
  "diagnostics": 5,
  "source_files_unchanged": true
}

São 38 testes do CSV e oito do modelo de revisões. Testes de links do sistema de arquivos podem ser marcados como ignorados quando o sistema operacional não permite criá-los; leia também essa contagem. Um teste ignorado não equivale a um teste aprovado.

Para guardar o relatório, crie uma pasta nova e indique-a:

mkdir resultados-aula
py -B public/blog/exemplos/run_examples.py --output-dir resultados-aula

Troque py por python3 quando necessário. O arquivo será resultados-aula/invalid-report.json. Uma segunda execução nessa pasta é recusada para preservar o relatório anterior. Escolha outra pasta; não apague evidências apenas para fazer o comando passar.

4. Preservar significa não sobrescrever

O validador agora cria o relatório em modo exclusivo. Se o destino já existe, inclusive como hard link ou link simbólico, a operação falha com código 2. Comparar apenas nomes ou caminhos resolvidos não era suficiente: dois caminhos diferentes podem representar o mesmo arquivo.

Os testes novos reproduzem esse caso usando arquivos sintéticos. A proteção evita sobrescrever destinos existentes; ela não torna a gravação resistente a falhas de energia nem garante que uma gravação interrompida deixe um JSON completo. Confira a conclusão do comando antes de usar o relatório.

Referência: modo de criação exclusiva do Python.

5. Faça uma demonstração que você consegue explicar

Mostre a amostra problemática, execute o comando, abra o relatório e explique por que seis registros geraram cinco diagnósticos. Depois diferencie uma restauração de conteúdo de uma repetição de pedido.

Por que as duas duplicatas são sinalizadas?

O arquivo não informa qual ocorrência deve prevalecer. O validador aponta as duas sem decidir silenciosamente qual venda manter.

Por que código 1 pode ser esperado?

No validador, significa que os dados violaram uma regra. Código 2 indica problema operacional. O executor reconhece que a amostra problemática deve terminar com 1 e só então aprova essa etapa.

Restaurar a revisão 1 deveria voltar o número para 1?

Não neste modelo. O conteúdo antigo passa a ser o conteúdo de uma nova revisão, preservando a evidência da restauração. O exemplo separado está no artigo sobre revisões.

Um teste offline comprova a disponibilidade de uma API?

Não. Uma fixture verifica um comportamento controlado. A chamada real verifica outra fronteira, em uma execução específica. Veja o artigo sobre SDKs.

O que este material não comprova

Os registros são fictícios. Estes testes não executam o backend do DataFlow, não comprovam disponibilidade da API Frankfurter e não certificam arquivos reais. Os exemplos são pequenos e delimitados.

Uma demonstração individual deve ser apresentada como tutorial. Uma palestra, público atendido ou contribuição aceita por outra comunidade só devem ser registrados depois de acontecerem. Este material é preparação, não evidência de um evento realizado.
